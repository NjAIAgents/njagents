Other possible causes
  1. The approval commits, but the read-back hits a replica that has not caught up, so the request only looks unchanged.
    Confirm: Reading the request from the primary right after the call shows it approved
    Less likely because the service logs 'approval not committed' on every failing call, which a lagging replica would not produce
  2. assertReviewer accepts the caller without checking the request, so a non-reviewer's decision is silently dropped.
    Confirm: The failing calls come from users who are not reviewers on that request
    Less likely because the log line is a persistence warning from the catch, not an authorisation refusal, and Northwind's callers are reviewers
